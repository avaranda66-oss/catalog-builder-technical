# Story 2.2 — Adaptador Supabase da biblioteca

**Status:** Done  
**Epic:** 2 — Biblioteca e persistência  
**Origem:** `docs/briefing.md`, FR-01/FR-09, NFR-03/NFR-04

## História

Como sistema, quero implementar a porta de catálogo sobre Supabase sem espalhar consultas pela interface, para que autenticação, RLS e conflitos possam evoluir sem redesenhar o editor.

## Critérios de aceite

- [x] O adaptador implementa `CatalogRepository` e não importa React ou Zustand.
- [x] Leitura valida catálogo e produtos antes de expor o snapshot ao editor.
- [x] Gravação usa `version` como controle otimista e retorna conflito quando nenhuma linha é atualizada.
- [x] Produtos são enviados em lote ao adaptador, sem segredos ou tokens no domínio.
- [x] Páginas continuam explicitamente pendentes até existir a migration de documentos.
- [x] Testes usam um cliente fake; nenhum teste grava no projeto Supabase real.

## Dev Agent Record

### Completion notes

O adaptador Supabase implementa a mesma porta usada pelo adaptador em memória, valida linhas na entrada e usa atualização condicional por `version`. Ele cobre o schema existente sem fingir que páginas já têm persistência relacional; essa parte permanece bloqueada pela migration de documentos.

### Validation

`npm test` passou com 17 casos; `npm run typecheck` passou; `npm run build` passou com 1 worker e typecheck externo (o modo padrão é bloqueado por `spawn EPERM` do sandbox). Os testes usam apenas um cliente fake e não acessam o projeto remoto.
