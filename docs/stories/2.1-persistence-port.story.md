# Story 2.1 — Porta de persistência e conflitos

**Status:** Done  
**Epic:** 2 — Biblioteca e persistência  
**Origem:** `docs/briefing.md`, FR-01/FR-09, NFR-04/NFR-05

## História

Como editor técnico, quero salvar um snapshot por revisão e receber um conflito quando outra pessoa já salvou, para que meu rascunho nunca seja perdido silenciosamente.

## Critérios de aceite

- [x] O domínio expõe uma porta de repositório sem dependência de Supabase ou React.
- [x] O adaptador em memória permite validar carga, cópia defensiva e gravação concorrente.
- [x] A revisão é incrementada no servidor/adaptador e o `expectedRevision` é obrigatório.
- [x] Conflitos retornam erro tipado com revisão esperada e atual, preservando o snapshot atual.
- [x] O CLI valida snapshots JSON usando os mesmos contratos de domínio.
- [x] Casos válidos, conflito e imutabilidade têm testes automatizados.

## Dev Agent Record

### Completion notes

A porta `CatalogRepository` e o `MemoryCatalogRepository` estabelecem a fronteira entre domínio e infraestrutura. Cada gravação exige a revisão observada e devolve `RevisionConflictError` sem substituir o snapshot atual. O comando `catalog:validate` usa os contratos Zod e retorna JSON próprio para automação.

### Validation

`npm test` passou com 14 casos; `npm run typecheck` passou; `npm run lint -- --quiet` passou; `npm run build` passou com 1 worker e typecheck externo (o modo padrão é bloqueado por `spawn EPERM` do sandbox); `npm run catalog:validate -- validate-product tests/fixtures/product-valid.json` retornou `valid: true`.
