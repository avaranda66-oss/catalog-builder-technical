# Story 2.3 — Persistência do documento e workspace

**Status:** Done  
**Epic:** 2 — Biblioteca e persistência  
**Origem:** `docs/briefing.md`, FR-01/FR-02/FR-05/FR-07/FR-09, NFR-03/NFR-04

## História

Como equipe técnica, quero persistir páginas, blocos, versões, revisões e vínculos da biblioteca mestre, para que o editor visual possa construir PDFs completos sem perder histórico nem controle de acesso.

## Critérios de aceite

- [x] O schema representa páginas A4 e seções ordenáveis sem guardar toda a composição em um único campo opaco.
- [x] Cada versão publicada preserva um snapshot imutável do documento.
- [x] Uma revisão registra autor, revisor, decisão e observação, impedindo autoaprovação.
- [x] Produtos podem ser reutilizados em mais de um catálogo por uma tabela de vínculo explícita.
- [x] Propostas de edição/importação/IA possuem ciclo de vida persistível.
- [x] Membros possuem papel por catálogo (`admin`, `editor`, `reviewer`, `viewer`).
- [x] RLS das tabelas novas exige associação ao catálogo ou perfil administrador.
- [x] A migration é local e validada por teste estático; nenhum comando grava no projeto Supabase remoto.

## Decisão provisória

Os quatro papéis cobrem o fluxo mostrado no baseline. A matriz final de permissões pode restringir operações por caso de uso antes do deploy; a migration não altera as políticas permissivas legadas de `00003`.
